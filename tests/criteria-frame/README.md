## Explicit sort helper and accepted boundary

```ts
createTableSortFn<T extends object>(
  definition: SortFnDef<NativeFeatures, T>,
): CreatedSortFn<NativeFeatures, T>
```

This source-only helper uses public-root **actual TanStack constructSortFn**. It
captures own data sort (required function) and optional resolver (supplied-invalid/
accessor/inherited metadata rejects), copies only the new known configuration,
records exact returned identity/ports/definition/original created receiver privately,
and freezes its new function/config. It never freezes input definition/app callbacks
or invokes them at construction. The return type remains the actual vendor type;
runtime freezing is not a claim that vendor properties are statically readonly.

Private `guardTableSortFn` recognizes only exact helper results or these exact six
public-root built-ins: alphanumeric, alphanumericCaseSensitive, basic, datetime,
text and textCaseSensitive. It uses the real factory again with separately guarded
captured resolver/comparator callbacks. Resolver retains bare-call undefined receiver;
sort retains the **original created function** receiver, not the local clone. Argument
order/results/exceptions are preserved subject to before/after denial gates.

Unregistered constructed/ambiguous functions with own/inherited sort or
resolveDataValue metadata reject before invocation, including copies/proxies and
accessors. No Function.toString/shape/prototype proof or caller registration setter.
Prototype metadata reflection is bounded and guarded, not a universal Proxy defense.
Ordinary bare comparators are one opaque app invocation: internally called hidden app
closures/coercions are app-owned and cannot be interrupted by this outer boundary.

The actual installed key is **sortFn**, not sortingFn. For auto/string paths, v9's
sorted model calls static column_getSortFn, so merely overriding a method would be
ineffective. The protected adapter wraps actual resolved accessors first, resolves
the currently sorted auto/string columns through real vendor selection, and captures
the selected guarded comparator in the actual vendor-owned resolved column def.
No registry names/features are invented or changed. Manual server/complete sorting
skips that resolution, preserving supplied order/no local sorting. Omitted raw legacy
still accepts ordinary vendor-constructed results without the new helper restriction.
