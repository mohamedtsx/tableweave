allocate `createCriteriaCommitCell`. No changing companion bridge is imported.

Internal `createCriteriaToolbarStore(kind, libraryLocalFactory)` has:

- `commit(opaqueInput, optionalRenderDiscriminant)`: actual config layout, no
  per-config cleanup; recaptures consumed target data under its operation guard
  and rejects disagreement with the render association;
- `getSnapshot()/subscribe()`: **version object only**, not values/readiness;
- `getMode()`: committed route metadata, never permission;
- `read() -> current committed frame | null` and `require(exactActor)`:
  always require actual F3 and genuine current F1/P permission.

unavailable.`. Underlying F3 keeps its actual `criteria.commit.unavailable` and

is rendered or logged. Denied surfaces use owned default text, not private error
messages from an invalid candidate. This is UI provenance, not backend auth or a
sandbox for arbitrary application callback bodies.

`Route` and stable surfaces subscribe, not the host. Inline props reallocation can
therefore commit a new actor without notification -> parent -> new-props loops.
Only committed `{ports, origin, actor}`, actual cell/empty-slot references and
guarded presentation flow to a surface; candidate props never do. Initial supplied-
criteria SSR/prelayout renders a fixed owned neutral status, not candidate labels,

The actual F3 cell performs genuine P-issued registration/cleanup. The host also

## Search: slots, deadlines and original receipts

All adopted authoritative values live in empty F3 slots: draft text/base/sequence/
deadline; IME; monotonic local sequence; notice; exact submission receipt; native
work handle/deadline; locale/time-zone edit session. React observes versions, not
private draft value state. Accepted C snapshots are read live through genuine
before/after guards, never stored as an accepted-state mirror.

- Original accepted **search TEXT** is the baseline. Page/sort/query refresh with
  unchanged text does not invalidate an eligible draft or restart its deadline.
- A receipt retains the original actual `StateProposal`, its sequence and therefore
  original proposal query **object** and revision. Older acceptance requires
  `receipt.sequence < draft.sequence`, accepted revision >= original proposal
  revision, and `state.query === receipt.proposal.transition.state.query`.
  Selection overrides still preserve that original query object. Reject has no
  notification and is not guessed to be acceptance. An independently normalized
  external query with equal text is not the original receipt.
- Eligible newer text stays visible during older acceptance before reconciliation;
  it is rebased rather than transiently replaced by older accepted text. That
  baseline rebase retains the original raw rescheduling semantics. Locale/time-
  zone session changes and disabling end ineligible local intent, matching the
  raw semantic-owner behavior without treating every query object as a reset.
- Submit checks actor/P/current actual CD/schema, IME, sequence and live accepted
  text, then rechecks immediately before real `C.dispatch`. Callback reentry cannot
  clear a newer sequence or write/read replacement B. Before and after existing
  `observeMutation`, actual C baseline and genuine actor are reread; no callback
  is an acceptance or backend authorization proof.
- Every actual edit has an original deadline. F3 cancels A work on valid B commit;
  the stable subscribed surface explicitly rearms B for remaining time from an
  eligible draft's original deadline. No full debounce restart due merely to
  config allocation and no A timer calling a latest B submit callback. No timer
  is created by the constructor/mount/config capture; only explicit eligible
  action/rearm uses F3 `timeout`/`cancelWork`. No raw adopted setTimeout/latest ref.
- Composition blocks both debounce and Enter until end; end reads the input only
  after checking its captured actor. Escape cancels the local edit, while Clear
  explicitly commits empty search and invalidates RAC's preceding onChange timer.
- Controlled proposal rejection/onRequest failure never fabricates acceptance.
  Exact proposals/accept/reject/selection retirement and fetching stay app-owned.
