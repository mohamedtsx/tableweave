## Exact actual additive API

```ts
revokeReorderInteraction(interaction: unknown): undefined
```

It is a free **release-only** function exported only by the explicit client
`@tableweave/react/reordering-controller` source index. The actual current index
has **13 runtime /13 type exports**: the original12 runtime exports plus this one,
with all original13 types, S/T invariance and NoInfer roles unchanged. Capture/begin
method signatures, original admission method keys and snapshot own-key shape remain
unchanged. No root/default/contracts/criteria/pure helper edge, manifest, configuration
or dependency change accompanies this export. Bare-alias source compilation is not
ordinary emitted/installed/packed availability proof.

The revoker authenticates exact issuance by WeakMap identity before any alleged
property. Its only call is that registry lookup; its only mutation is setting an
owned boolean irreversibly true. It returns undefined for unknown, null, primitive,
function, copied, proxied, already-ended/duplicate and foreign **token-kind** inputs.
There is no permitting boolean or provenance oracle. A genuine interaction from
another admission is a distinct release capability: releasing one never touches
another cut/table; passing B's token to A.begin still fails A's exact local registry.
The free function does not look up an owner from a receiver or select a latest cut.

**No revocation-time source/model/P/C/app/native read, authority check/grant,
reflection, promise, clock, scheduler, listener, pure coordinator call or backend
mutation occurs.** It is safe to release a known cut even after its renderer actor
has retired, without finding a new source or proving new permission. That safety
does not itself wire actual R/N retirement; C1b must do so under a separate lease.

## Physical flag, exact ACT propagation, no orphan

The module-global registry is `WeakMap<issuedToken, {revoked:boolean}>`. The value
is a plain one-bit data object, never a per-token owner closure/backlink, lease,
T/row/model/view/frame/query/config/callback container. The runtime interaction token
remains an empty frozen opaque object. Old tokens cannot reach an admission through
the new global value; actual GC behavior is not measured by static/type evidence.

One finite private slot still owns the original captured frame. Replacing/retiring
the slot ends its physical flag. Begin consumes its nonce while preserving that
exact flag for the active attempt, **before pure placement parsing**. The original
attempt carries it through every ACT read. A revoked current/owned cut denies with
fixed blocked/unavailable metadata before entering pure, without reading placement
or source ports. Foreign/borrowed receivers retain their original denial semantics.

`checkAt(ACT)` now rejects a revoked exact flag even at identical SRC/UI counters.
The private interruption receipt is single-use/current-boundary, and same-UI recovery
additionally matches the actual active attempt's physical object. Source/lease,
registered source signature and truthful metadata still must validate. Unknown,
copied, public, foreign or replayed exception values cannot suppress cleanup.

After frame extraction, the existing adapter performs one final fixed ACT check
using that same original attempt, before pure parses the returned owned data. The
native/eligibility/U1 frame-construction body remains byte-identical. This last exit
also catches flag changes during frame extraction; it is not a fresh/latest cut or
an app-supplied before-token callback gate. The unchanged pure `capture.frame`
returns frozen own-data stamp/page-ID/base-revision values (capture.ts:112–171).
Pure parsing and the single fixed internal observer then run without an external
callback window before pending/token return. The observer's exact self-pending
credit remains unchanged, and final begin checks are fixed metadata only.

An ordinary UI-only revoke before creation blocks with otherwise-live source and
same app epoch; a fresh genuine capture can start normally. No coordinator invalidate,
fake rejection/ack, epoch regrant, rollback, new engine or hidden undelivered operation
is used. Completed consumed cuts end after final checks. Once started returns,
the operation belongs to the application calling path: revoking that row token does
not clear/settle/ack/purge pending, change source/owner epochs or undo backend effects.
Accepted/indeterminate transport remains pending until actual source/ack rules resolve.

### Source failure always remains distinct

Original thrown callbacks, malformed/changed truthful metadata, actual P/access/
source/lease loss still fail closed, even if the physical flag was revoked too.
SRC validation precedes physical interruption classification; original failure is
not masked by a finally flag check. OBSERVE/empty-ID reads do not depend on row flags.
Settle/ack/reconcile, original callbacks/receivers/returns, query-first C assignment,
source/model continuation, pre-entry waiting and genuine in-flight pure detach rules
remain B2. Their bodies are source-compared unchanged in this own lane.

No waiting/offline/new-owner continuation is added. The application still retains
its actual model producer above optional UI, holds correlated notices until genuine
commit, and owns real disconnect/C/P/resource/transport termination. Release is not
backend cancellation, a new authorizer or a replacement for genuine native authority.

## Metadata/pruning and notification limit

The global revoker does **not** advance SRC/UI, bump any version, publish or schedule.
Row capture/revoke alone must not manufacture UI ABA for saved nav/command receipts.
Existing guarded-command and actual pending transitions still advance their original
UI generation; those genuine events are independent of this release primitive.

`getSnapshot()` locally prunes a flagged current slot before returning interaction
metadata, so `interaction:true` cannot advertise that revoked origin as usable. The
first prune may produce one truthful existing-shape snapshot/version; repeated reads
are stable. It reads no app/source/native port for pruning and schedules nothing;
the existing C-disposed check remains the original getter behavior. The finite frame
buffer can remain owned until that local prune or real retirement, not through a
global token→owner link. `observeReorderUI().joined` still means physical UI/model
association, not a row permission grant, and is not changed by a row-only release.

**Notification limit:** cleanup itself does not wake subscribers. A preexisting
queued genuine publication or a later real UI publication owns display updates;
there is no version-per-read/infinite render loop. Event-time begin checks the flag
even if no render/getSnapshot happened. C1b must couple the real issuer/N retirement
to exact-token release and its real UI publication, not infer permission from cached
visual booleans or add a post-token source gate.
