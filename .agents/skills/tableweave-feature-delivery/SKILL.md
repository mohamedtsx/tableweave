# Deliver a requirement-backed slice

Read [project map](../../../PROJECT.md), relevant [product owner](../../../product/README.md)
and linked technical contract, then the assigned [packet](../../../docs/planning/work-packets.md).

1. Confirm execution/install/target authority and ready dependencies in TASKS.
   Inspect actual implementation, manifests/lockfile, tests and executable README
   commands. No scaffold/new dependency just because a guide mentions it.
2. Name FR/D/AC/gate coverage and the observable result. Distinguish missing
   product policy from engineering proof/publication inputs. Escalate true
   contradictions; preserve all stable-v1 scope.
3. Use one owner per group. Trace definition validation → draft/command → accepted
   transition → native projection or app query → identity-tagged resource → view/
   actions. Preserve atomic resets, stable IDs, field ownership and scope guards.
4. Match actual v9/v3/selected sortable generation docs/types. No removed native
   global callbacks, second engine/state mirror, implicit fetching/persistence or
   unauthorized `.repo/` imports. Keep contracts server-safe and sortable optional.
5. Verify meaningful invalid/stale/race/controlled-owner/focus and cross-feature
   boundaries, not only happy-path types. App persistence/authorization outcomes
   remain distinct from UI success.
6. Review diff and affected consumers; fix in-scope issues, update owning docs/
   acceptance and exact evidence. Hand off remaining gates honestly. Do not
   claim a proposed API, mock, workspace alias or planned command proves release.

For UI use [UI workflow](../tableweave-ui-workflow/SKILL.md); for check selection
use [verification](../tableweave-verification/SKILL.md). Dependency/API changes
that revise HLD choices need an ADR disposition, not silent source drift.
