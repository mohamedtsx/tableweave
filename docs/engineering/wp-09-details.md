## Actual candidate entry and ports

`packages/heroui/src/details/index.ts` exposes `useDetailsSession`, `DetailsShell`,
`DetailsTrigger`, `englishDetailsMessages` and own types. The package root now
emits these candidate exports through main-owned integration. Emitted build
and own declarations still require separate actual tarball/type/runtime proof;
source-fixture success is not package or full WP-09 acceptance.

DetailsContext identifies definition/dataset/scope/access and an application
invalidation epoch. DetailsAuthority additionally identifies rowId, target session
and request generation. The application advances those identities, owns transport/
cache/authorization/controlled cleanup and supplies loading/ready/error/missing
DetailsSource with matching provenance. No table wire-query request is repurposed
for record details, and page absence is not deletion. App callbacks/read ports are
not backend authorization tokens.

The session hook consumes the existing controller plus expected/current authority,
source, pure atomic current-committed port, optional Retry, visible/hidden field
IDs, dirty-change policy, outcome observation and safe
focus fallback. Optional native row must be genuine and current; never manufacture
one for an unloaded record. Arbitrary app content has no built-in field template.

DetailsPort.read returns {authority,nativeFrame?}; optional native frame carries
immutable origin, actual controller owner and genuine committed view. Untagged
retained views and mere shared record/query identity cannot establish provenance.
App captures original frame tags at commit, never retags an old frame for a new
scope. Missing/mismatched proof omits only the optional row, not valid detail data.
Primitive metadata/callback capture rejects accessors without invoking them;
denied lifecycle short-circuits old source getters and private errors.

requestOpen and requestClose share the async policy/identity checks and submit the
existing details.change command. Outcomes distinguish blocked/stale/busy/failed/
rejected/noop, submitted proposal and committed transition notification failures.
Proposed is not accepted visibility; controller.reject emits no subscription event.
Pending confirmation preserves the current mounted draft but cannot close a newer
session after resolution. Application-accepted transitions remain authoritative.
Request generation is freshness, not target/session lifetime. Generation-before-
parent-prop lag masks stale record/row while the same permitted custom form stays
mounted through loading/error/ready. True scope/owner/access/epoch/target/session
invalidation removes private content immediately. No retained-record cache is
invented to preserve the form's local application-owned draft.
