## Agree a representative contract before trial

Choose the actual table/use case and expected outcomes with the authorized app
owner; record enabled features, intentional exclusions and tested boundaries before
observing results. This is not a second all-FR checklist or post-hoc passing count.
The full [stable contract](../../product/release-gates.md) remains unchanged.

| Boundary | Representative acceptance observation required in the actual app |
| --- | --- |
| Typed extension seam | Real typed table, stable field/row IDs, custom cell, exclusive field owner, arbitrary custom details/form and row/bulk action; not only fake public-model callbacks. |
| Query/control | Actual accepted/rejected controlled transitions are atomic; builder/toolbar ownership, builder-only Clear and distinct Cancel hold. Observe real query/source/request bindings and app transport outcomes; do not invent duplicate-read counters. |
| Selection/page/recovery | Actual native table DOM/ARIA and selection/pager targets remain coherent through query/page/loading/retained/error/retry outcomes. Selected IDs are not loaded records, authorization or promises of successful action. |
| Retirement/races | Scope/access/definition loss, unmount/reconnect and A→B→A transitions do not permit late results, stale callbacks, async options/retries/queued proposals or old actions to revive retired targets. Preserve source/context/revision identities; old scope strings are not new authority. |
| Details/focus | App-owned dirty form, close versus cancel/unsaved handling, failure/retry and keyboard focus return operate on the actual row/source. Narrow/layout changes must not return focus to an obsolete row/scope or retain private stale details. |
| Mutation acknowledgement | For selected eligible manual movement/actions, pending/rejected/unknown/success outcomes and persistence acknowledgements are truthful and context/revision-bound. Unknown completion is not persisted success. Do not activate drag, repair vendors or claim manual moves waive G-02. |

Fetching, backend authorization/query translation/actions and persistence remain
application-owned. UI hiding, selected IDs, query schemas and model/source objects
are **not backend authorization**. Check the app-owner boundary independently when
authorized; no fabricated P/certificate or synthetic reader proves production
permissions/security. If that boundary is not exercised, label it NOT_RUN and
exclude the claim rather than borrowing acceptance from a library fixture.

Use public synthetic records **inside the real authorized app context**. Declared
mock/synthetic backend portions stay explicit limitations. Native DOM/focus checks
do not replace actual screen-reader, supported desktop/mobile, touch or other
manual acceptance; Chromium/WebKit emulation is not Safari or a real mobile device.
Those user-deferred inputs remain unknown, never fabricated versions/zero failures.

## Failure, rollback and decision boundaries

Preserve unrelated WIP/data and actual failed/partial evidence. App-owner rollback
uses only its separately approved paths/operator/data/deployment plan; do not
blindly revert the workspace or assume a tag change removes installed code.
A library defect returns to a new library-owner fix lease and affected FINAL proof;
do not weaken requirements, patch a vendor, or modify read-only references to fit
the consumer. Successful integration authorizes no automatic deploy/npm publication,
version change, library merge or changes to another consumer.

Observe friction with the advisory30-minute typed-table task if selected. Neither
a fixed participant count nor an invented completion-time threshold is a stable
blocker. Do not solicit deferred targets, people, runners or account access now.

Use the [one FINAL phase](../planning/final-verification-phase.md) and
[WP-15 scope](../planning/work-packets.md#wp-15-real-consumer-and-stable-readiness):
individual packet evidence and separate unmerged PRs, no promotion of historical
or cumulative results into untested exact-head acceptance. Real consumer, manual/AT,
supported devices, approved reference performance, current archives/CI and publication
rights remain distinct requirements. This documentation task grants no AC-29,
WP-15 or stable approval. **Keep drag/G-02 blocked.**
